# 即兴对话中文键入与本地自适应设计

## 目标

让学习者在即兴对话的“键入”入口输入英文或中文。中文会在提交前译成英文，学习气泡与评分均使用该英文，同时保留原中文供学习者核对。每次有效回答后，对方紧接着的一句会根据回答内容和下一轮练习方向作本地化承接与追问，而不是原样播放固定台词。

## 已确认范围

- 仅修改当前本地工作目录；不提交、推送或更新 GitHub 仓库。
- 保持纯静态网页；不增加后端、密钥、登录、付费 API 或生成式 AI 服务。
- 中文翻译复用页面已有的中译英网络翻译能力；没有网络或翻译服务不可用时，不能伪造英文，保留输入并提示重试或改输英文。
- 英文键入、录音转写、录音回放、提示、参考说法、文本质量评分和既有场景资源均保留。
- “自适应”是本地规则和模板：会根据回答是否过短、是否肯定/否定、是否含时间、地点、偏好、理由或下一步动作来选择不同的承接和问题。它不是能理解任意开放表达的云端 AI。

## 中文键入流程

1. 键入入口改为“输入英文或中文都可以”，并显示对应说明。
2. 提交文本不含中文时，沿用现有英文流程：显示原英文，异步译成中文，按该英文评分。
3. 提交文本含中文时，按钮进入“正在翻译…”状态，调用已有的中译英函数。
4. 译文必须是非空、无中文字符的英文文本。成功后，用户气泡上方显示英文，中文区域显示用户原始中文；评分与下一句自适应均使用英文译文。
5. 翻译失败时不推进回合、不写入 0 分回答、不清空输入框；显示“暂时无法把中文译成英文，请检查网络后重试，或改用英文输入”。

## 本地自适应对话流程

1. 每个场景的首句仍使用既有 A 台词；原始场景数据不被改写。
2. 学习者完成一个 B 回合（键入英文、中文译文或录音转写）后，程序查看紧随其后的 A 台词和再下一轮 B 的 `dir`/`sugs`。
3. 对方的紧接 A 台词由本地生成的副本替代：
   - 回答太短或不够完整时，先礼貌要求补充；
   - 含明确时间、地点、偏好、肯定/否定、理由或行动时，承接该信息；
   - 然后按下一轮 B 的练习方向发出相应追问，例如时间、地点、选择、理由、计划或确认。
4. 生成台词同时提供固定中文译文。下一轮仍使用原场景的 B 方向与参考说法，因此场景训练目标、轮数、提示和示范内容保持可用。
5. 如果没有英文回答（跳过或语音未转写），不生成自适应台词，照常使用原 A 台词，避免以不存在的回答编造承接。
6. 自适应台词只存在于本次练习的运行态；重新开始场景会从原始资源重新生成，且不会污染内置、导入或自定义资源。

## 评分边界

- 仍只按英文文本的切题性、完整性和自然性评分，不按音质或发音质量评分。
- 中文输入成功翻译后按译文评分；译文失败不算完成该轮，也不改变已有成绩。
- 本地自适应只决定对方的承接话术，不改变用户原有回答分数。

## 验收条件

1. 键入中文“我明天下午到”后，用户气泡出现英文译文与这句中文，评分输入是英文译文。
2. 翻译服务失败时，用户可以在原输入框内重试，回合不前进，且不会显示假英文。
3. 对“明天下午到”和“我不知道”两种回答，下一句对方台词不同，且前者明确承接时间、后者请求补充。
4. 自适应台词的追问与下一轮 B 的 `dir` 一致；原始 `sc.lines` 不被修改。
5. 无文字录音和跳过回合仍播放原有下一句；现有导入、翻译、生词本、资源解析与即兴对话测试继续通过。
